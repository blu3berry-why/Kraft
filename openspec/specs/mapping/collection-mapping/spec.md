# collection-mapping Specification

## Purpose

Defines how Kraft maps a property whose type is a single-element collection (List, Set, Collection, Iterable, Array and their Mutable variants): which element operations apply, which collection-type conversions are generated or refused, and how nullability and nesting behave at each level.

Unless a scenario says otherwise, every scenario uses `data class ItemSource(val id: Int)`, `data class ItemDto(val id: Int)`, a `Src`/`Tgt` pair with one property `items` of the stated types, and `@MapConfig(source = Src::class, target = Tgt::class) object M`. `toItemDto()` is the nested mapper Kraft generates for `ItemSource → ItemDto`.

## Requirements

### Requirement: Supported collection types
Kraft SHALL map element-wise between properties whose types are any of `List`, `Set`, `Collection`, `Iterable`, `Array`, `MutableList`, `MutableSet` and `MutableCollection`, when the element types differ and an element operation exists. Element operations are: a nested mapper, an enum mapper, a `@KraftConverter`, and a value-class wrap or unwrap.

#### Scenario: Collection to Collection
- **WHEN** `Src.items: Collection<ItemSource>` and `Tgt.items: Collection<ItemDto>`
- **THEN** the mapper assigns `items = this.items.map { it.toItemDto() }`

#### Scenario: Array to Array
- **WHEN** `Src.items: Array<ItemSource>` and `Tgt.items: Array<ItemDto>`
- **THEN** the mapper assigns `items = this.items.map { it.toItemDto() }.toTypedArray()`

#### Scenario: MutableList to MutableList
- **WHEN** `Src.items: MutableList<ItemSource>` and `Tgt.items: MutableList<ItemDto>`
- **THEN** the mapper assigns `items = this.items.map { it.toItemDto() }.toMutableList()`

#### Scenario: Existing List and Set output is unchanged
- **WHEN** `Src.items: List<ItemSource>` / `Tgt.items: List<ItemDto>`, and separately `Set<ItemSource>` / `Set<ItemDto>`
- **THEN** the mappers assign `this.items.map { it.toItemDto() }` and `this.items.map { it.toItemDto() }.toSet()` respectively, exactly as in 0.13

### Requirement: Lossless conversions between collection types
When the source and target collection types differ, Kraft SHALL generate the conversion if it keeps every element: any source type into `List`, `Collection`, `Iterable`, `Array`, `MutableList` or `MutableCollection`, and `Set` or `MutableSet` into `Set` or `MutableSet`.

#### Scenario: Array to List
- **WHEN** `Src.items: Array<ItemSource>` and `Tgt.items: List<ItemDto>`
- **THEN** the mapper assigns `items = this.items.map { it.toItemDto() }`

#### Scenario: Set to List
- **WHEN** `Src.items: Set<ItemSource>` and `Tgt.items: List<ItemDto>`
- **THEN** the mapper assigns `items = this.items.map { it.toItemDto() }`

#### Scenario: Iterable to MutableCollection
- **WHEN** `Src.items: Iterable<ItemSource>` and `Tgt.items: MutableCollection<ItemDto>`
- **THEN** the mapper assigns `items = this.items.map { it.toItemDto() }.toMutableList()`

#### Scenario: Same elements, different collection type
- **WHEN** `Src.tags: Array<String>` and `Tgt.tags: List<String>`
- **THEN** the mapper assigns `tags = this.tags.toList()`

#### Scenario: Target already a supertype
- **WHEN** `Src.tags: List<String>` and `Tgt.tags: Collection<String>`
- **THEN** the mapper assigns `tags = this.tags` with no copy

### Requirement: Conversions into a Set from a non-Set are refused
Kraft SHALL fail compilation with KRAFT-E063 when the target is `Set` or `MutableSet` and the source is not `Set` or `MutableSet`, because duplicate elements would be dropped silently. This SHALL also apply to the reverse mapper generated by `@MapReverse`.
#### Scenario: List to Set
- **WHEN** `Src.items: List<ItemSource>` and `Tgt.items: Set<ItemDto>`
- **THEN** compilation fails with `[KRAFT-E063] Cannot map property 'items': converting List<ItemSource> to Set<ItemDto> would drop duplicate elements.`
- **AND** the error contains `Change the target to List<ItemDto>, or map it with @MapUsing and call .toSet() explicitly.`
- **AND** no KRAFT-E005 type-mismatch error is reported for `items`: one cause, one error

#### Scenario: Reverse of Set to List
- **WHEN** `Src.items: Set<ItemSource>`, `Tgt.items: List<ItemDto>` and `M` is annotated `@MapReverse`
- **THEN** the forward mapper compiles as in "Set to List", and compilation fails with `[KRAFT-E063] Cannot map property 'items': converting List<ItemDto> to Set<ItemSource> would drop duplicate elements.`

### Requirement: Element operations reuse the scalar rules
Each element SHALL be mapped by the operation Kraft would use for a single property of the element types: an auto-detected nested mapper, an enum mapper, a `@KraftConverter` under its own name, or a value-class wrap/unwrap. A `@MapField` / `FieldMapping` rename SHALL select the source property.

#### Scenario: Named @KraftConverter on elements
- **WHEN** `@KraftConverter fun Foo.intoBar(): Bar` is registered (`Foo` and `Bar` are interfaces, so no nested mapper is generated for them), `Src.items: List<Foo>` and `Tgt.items: List<Bar>`
- **THEN** the mapper assigns `items = this.items.map { it.intoBar() }`

#### Scenario: Nested mapper takes precedence over a converter
- **WHEN** `@KraftConverter fun ItemSource.intoDto(): ItemDto` is registered, `Src.items: List<ItemSource>` and `Tgt.items: List<ItemDto>`
- **THEN** the mapper assigns `items = this.items.map { it.toItemDto() }`, as a single `ItemSource` property would resolve to the nested mapper

#### Scenario: Value class elements in an Array
- **WHEN** `@JvmInline value class UserId(val value: String)`, `Src.ids: Array<String>` and `Tgt.ids: List<UserId>`
- **THEN** the mapper assigns `ids = this.ids.map { UserId(it) }`

#### Scenario: Renamed Collection
- **WHEN** `Tgt.items: Collection<ItemDto>` is annotated `@MapField(counterPartName = "rows")` and `Src.rows: Array<ItemSource>`
- **THEN** the mapper assigns `items = this.rows.map { it.toItemDto() }`

#### Scenario: No element operation
- **WHEN** `Src.items: Collection<Int>` and `Tgt.items: Collection<String>` and no converter for `Int → String` is registered
- **THEN** compilation fails with the KRAFT-E005 type-mismatch error for `items`

### Requirement: Nullability at the container level
A nullable source container SHALL be safe-called. When the target container is non-null, the result SHALL fall back to the target type's empty value: `emptyList()` for `List`, `Collection` and `Iterable`, `mutableListOf()` for `MutableList` and `MutableCollection`, `emptySet()` for `Set`, `mutableSetOf()` for `MutableSet`, and `emptyArray()` for `Array`.

#### Scenario: Nullable Array into non-null List
- **WHEN** `Src.items: Array<ItemSource>?` and `Tgt.items: List<ItemDto>`
- **THEN** the mapper assigns `items = this.items?.map { it.toItemDto() } ?: emptyList()`

#### Scenario: Nullable into nullable
- **WHEN** `Src.items: Collection<ItemSource>?` and `Tgt.items: Collection<ItemDto>?`
- **THEN** the mapper assigns `items = this.items?.map { it.toItemDto() }`

### Requirement: Nullability at the element level
Nullable source elements SHALL map to nullable target elements through a safe call. Nullable source elements into non-null target elements SHALL be dropped with `mapNotNull`, as for `List` and `Set` in 0.13.

#### Scenario: Nullable elements kept
- **WHEN** `Src.items: Collection<ItemSource?>` and `Tgt.items: Collection<ItemDto?>`
- **THEN** the mapper assigns `items = this.items.map { it?.toItemDto() }`

#### Scenario: Nullable elements dropped
- **WHEN** `Src.items: Array<ItemSource?>` and `Tgt.items: List<ItemDto>`
- **THEN** the mapper assigns `items = this.items.mapNotNull { it?.toItemDto() }`

### Requirement: Nested collections
Collections whose elements are themselves collections or maps SHALL map recursively to any depth, applying the conversion, nullability and element rules independently at each level. Generated code SHALL NOT shadow lambda parameters: the innermost lambda uses `it`, and each enclosing lambda names its parameter `e<depth>`, counting from 0 at the outermost.

#### Scenario: List of lists
- **WHEN** `Src.grid: List<List<ItemSource>>` and `Tgt.grid: List<List<ItemDto>>`
- **THEN** the mapper assigns `grid = this.grid.map { e0 -> e0.map { it.toItemDto() } }`

#### Scenario: Inner nullable list into non-null list
- **WHEN** `Src.grid: List<List<ItemSource>?>` and `Tgt.grid: List<List<ItemDto>>`
- **THEN** the mapper assigns `grid = this.grid.map { e0 -> e0?.map { it.toItemDto() } ?: emptyList() }`

#### Scenario: No shadowing warnings
- **WHEN** the "List of lists" mapper is compiled with `allWarningsAsErrors = true`
- **THEN** compilation succeeds

#### Scenario: Lossy conversion at an inner level
- **WHEN** `Src.grid: List<List<ItemSource>>` and `Tgt.grid: List<Set<ItemDto>>`
- **THEN** compilation fails with `[KRAFT-E063] Cannot map property 'grid': converting List<ItemSource> to Set<ItemDto> would drop duplicate elements.`

### Requirement: Deprecated nested-mapping annotations keep 0.13 behaviour
`@MapNested` and `@MapConfig(nestedMappings = …)` are deprecated and SHALL NOT gain support for the collection types, conversions or nesting this change adds. They SHALL keep generating exactly the 0.13 output, including the existing `List` → `Set` conversion reached through an explicit `NestedMapping` with a `FieldMapping` rename.

#### Scenario: Legacy explicit NestedMapping List to Set is unchanged
- **WHEN** `@MapConfig(..., nestedMappings = [NestedMapping(ItemSource::class, ItemDto::class)], fieldMappings = [FieldMapping(source = "legacyRows", target = "rows")])`, `Src.legacyRows: List<ItemSource>` and `Tgt.rows: Set<ItemDto>`
- **THEN** the mapper assigns `rows = this.legacyRows.map { it.toItemDto() }.toSet()` with no new Kraft diagnostic

#### Scenario: @MapNested does not reach new collection types
- **WHEN** `Tgt.items: Collection<ItemDto>` is annotated `@MapNested` and `Src.items: Collection<ItemSource>`
- **THEN** the mapper output is identical to the same input without `@MapNested` (auto-detection produces it), and the only added diagnostics are those `@MapNested` produced in 0.13

#### Scenario: @MapNested sourceName is still honoured as a rename
- **WHEN** `Tgt.items: Collection<ItemDto>` is annotated `@MapNested(sourceName = "rows")` and `Src.rows: Array<ItemSource>`
- **THEN** the mapper assigns `items = this.rows.map { it.toItemDto() }`, the same as `@MapField(counterPartName = "rows")`, and never silently reads `Src.items`

### Requirement: Nested-mapper reason text
The KRAFT-E015 message SHALL NOT state that non-List collections are unsupported, and SHALL name the element type that is not a concrete mappable class.

#### Scenario: Interface element type
- **WHEN** `Tgt.items: List<Shape>` where `Shape` is an interface, annotated `@MapNested`, and `Src.items: List<ShapeDto>`
- **THEN** compilation fails with KRAFT-E015 for `items`, the message names `Shape`, and it does not contain `non-List collections are not supported`
